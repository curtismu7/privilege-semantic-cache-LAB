# Safety

What this lab does and does not do, in one page. The tests named here fail if it stops being true.

- **Nothing leaves the machine.** A stand-in encoder, a vector store stand-in, a mock model and a lab clock; the netguard refuses every outbound route and records the attempt (`server/test/netguard.test.js`; the doctor runs every scenario under it and asserts zero attempts). Hosts named anywhere in the lab are `.example` or `.invalid` (`server/test/static.test.js`).
- **Loopback only.** The server binds `127.0.0.1` unless `PSC_BIND` is set on purpose; the Host header must be a loopback name or on `LAB_ALLOWED_HOSTS` (421 otherwise); a write must be same-origin and JSON (403 and 415 otherwise), on every write route including the store and provider controls. Docker publishes `127.0.0.1:7847` only and the image runs as the non-root `node` user with a read-only file system and no capabilities (`scripts/compose.test.mjs`).
- **No credential anywhere.** The key has no credential field: any field the lab does not list is refused as unknown. The values shown as credentials in a trace are labelled lab mocks. Nothing secret is logged: a stdout line is `<time> <lab> decision step= actor= result= run=` and never holds a prompt or an answer.
- **Hostile input is bounded.** A prompt is a string of at most 20000 characters with a letter or digit in it; strictness is 0 to 1, a TTL a whole number from 1 ms to a week, a clock advance 0 ms to a week, a store and a provider state come from fixed lists; bodies over 128 KB are refused; each store holds at most 100 entries; workspace ids are 1 to 32 lowercase letters, digits and dashes and at most 20 exist (the least recently used is forgotten, never a refusal). Error messages never echo more than 40 characters of what the caller sent. User text is rendered as text by React and passed through `visible()`, so control and bidi characters show as escapes.
- **The web page is the only thing served besides `/api`.** It is served from `web/dist` with a content-security policy (`default-src 'self'`); a missing `/assets` file is a 404 and never the page. The tests run without a web build.
- **Nothing is claimed beyond the release notes.** The banner on every page, in presenter mode too, says what is simulated and that the encoder is not a real embedding model; the Limits page lists what the release notes say and what is the lab's own model (UNVERIFIED). Whether the cache is scoped by key only or also by user is an open question: the page shows a card with no result and the lab has no scenario for it.
- **Real mode is not built.** The header toggle shows Real disabled with the reason, and `POST /api/mode {"source":"real"}` answers 409 with the same words. Real, when it exists, is owner-run and read-only.
